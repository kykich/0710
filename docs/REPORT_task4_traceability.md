## Детализация по пунктам

### 1) Сохранение данных (JSON)

**Требование:** «инструмент должен сохранять данные (JSON / SQLite)».

**Реализация** — `rtk_app/jobs_store.py`: класс `JobsStore` хранит задания и
накопленные точки в едином JSON-файле `session/mcp_jobs.json`. Внутри — по
изолированному пространству на каждый MCP-сервер (`servers.<id>.jobs`,
`servers.<id>.data`). Запись атомарная (временный файл + `os.replace`),
битый файл не роняет сервер.

**Тест** — `tests/check_jobs.py`:

- §1 «файл JSON создан на диске», «задание читается из файла»;
- §5 «точки сохранены», «серия читается из файла».

---

### 2) Выполнение по расписанию

**Требование:** «инструмент должен выполняться по расписанию».

**Реализация** — в `JobsStore`:

- `add_job(kind, params, every_minutes, at, in_minutes)` — постановка задания
  (периодического или отложенного разового);
- `due_jobs()` — выбор НАСТУПИВШИХ заданий (`next_run <= сейчас`);
- `mark_run()` + `_advance()` — отметка исполнения, перепланирование
  периодического / завершение разового.

Так как MCP-серверы запускаются как stdio-подпроцессы **на время вызова**,
задания исполняются **лениво** (при любом обращении к серверу — `_run_due` в
`currency_server.get_rate`/`list_events`) либо **явно** через инструмент
`run_due()`. Персистентность состояния в JSON эмулирует «24/7» без демона.

**Тест** — `tests/check_jobs.py`:

- §2 «будущее задание не созрело», «разовое без времени созрело сразу»;
- §3 «просроченное периодическое созрело», «next_run сдвинут в будущее»,
  «после запуска задание больше не созрело»;
- §4 «разовое помечено done», «done-задание не попадает в due».

---

### 3) Возврат агрегированного результата

**Требование:** «инструмент должен возвращать агрегированный результат».

**Реализация:**

- `currency_server.rate_summary(from, to, period)` — агрегат по накопленным
  точкам: число точек, первая/последняя, минимум, максимум, среднее и
  изменение (абсолютное и %), с фильтром периода (`day`/`week`/`month`/`all`);
- `yandex_calendar_server.due_reminders()` — сводка наступивших напоминаний.

Выдача пользователю — «через модель по запросу»: инструмент возвращает
текст-агрегат, модель (агент) пересказывает его в ответе.

**Тест** — `tests/check_jobs.py` §5 (минимум/максимум/среднее/изменение);
live-прогон `rate_summary` (см. ниже).

---

### 4) Календарь — напоминалка до события

**Требование:** «добавить к mcp календарь — возможность работы по расписанию
как напоминалка до события».

**Реализация** — `yandex_calendar_server.py`:

- `schedule_reminder(uid|summary, date, lead_minutes, repeat_minutes, repeat_hours)`
  — момент напоминания = начало события − `lead_minutes`; создаётся задание
  `kind="reminder"` с параметрами `lead_minutes`/`repeat_minutes`;
- `list_reminders()`, `cancel_reminder(id)` — список/отмена;
- `due_reminders()` / `run_due()` — наступившие напоминания;
- ленивый прогон в `list_events`.

**Повтор напоминаний (п. 4a).** Параметр `repeat_minutes` (или удобный
`repeat_hours`, например `repeat_hours=1` — «раз в час») задаёт периодичность:
первое напоминание — за `lead_minutes` до начала, далее — каждые
`repeat_minutes`, **пока не наступит событие**. Вычисление следующего момента и
остановка — в `_next_reminder_time()`; завершение повторяющегося задания —
через `JobsStore.mark_fired(job_id, next_run="")`. Поддержка «раз в минуту»
(`repeat_minutes=1`) и «раз в час» (`repeat_hours=1`).

**Тест** — живой прогон: создание события → `schedule_reminder(repeat_hours=1)`
→ `due_reminders` выдал напоминание и **переназначил** следующий запуск (не
`done`) → `cancel_reminder` очищает. Офлайн — `tests/check_reminders.py`
(разовое/повтор/остановка у начала события/формат периода).

---

### 5) Конвертер — расписание, сбор в JSON, агрегат

**Требование:** «добавить к mcp Конвертер — работу по расписанию, сбор
ответов в json, вывод агрегированного результата».

**Реализация** — `currency_server.py`:

- `schedule_rate(from, to, every_minutes, first_now)` — периодический сбор
  курса пары в JSON;
- `collect_now(from, to)` — внеплановое разовое сохранение точки;
- `run_due()` / ленивый `_run_due` — исполнение созревших заданий;
- `list_jobs()`, `cancel_job(id)` — управление заданиями;
- `rate_points(from, to, limit)` — накопленные точки;
- `rate_summary(from, to, period)` — агрегат.

Точки пишутся в серию `"FROM>TO"` (пространство `currency` файла
`session/mcp_jobs.json`).

**Тест** — `tests/check_jobs.py` (механизм + агрегат); живой прогон
`schedule_rate(first_now=True)` → `collect_now` → `rate_points` →
`rate_summary`.

## Как запускать проверки

Автономные (офлайн, без сети) тесты механизма:

```bash
python tests/check_jobs.py        # задания расписания (JSON, агрегат)
python tests/check_reminders.py   # повторяющиеся напоминания календаря
```

Живые прогоны MCP-серверов (нужны `mcp`, сеть и ключи `exch.txt`/`ya.txt`):

```bash
python client.py currency_server.py   # список инструментов «Конвертера»
python client.py                      # список инструментов календаря
```

Либо из интерфейса/агента — выбор сервера в блоке «MCP» и запрос к модели.
