**Тема задачи (`docs/task5.md`):** несколько MCP-инструментов, собранных в
**композицию** (пайплайн) с отдельной кнопкой запуска в разделе MCP.

Документ связывает каждый пункт `task5.md` с конкретным кодом (реализацией) и
проверкой (тестом).

## Детализация по пунктам

### 1) «Календарь» — состояние событий на 7 дней, раз в минуту

**Требование:** «"календарь" проверяет каждую минуту состояние событий на
ближайшие 7 дней с текущей даты».

**Реализация:**

- окно обзора — `config.COMPOSITION_DAYS_AHEAD = 7`;
- фоновый **тик** — `web/server.py::_composition_tick_loop(interval)`,
  запускается из `serve()` через `_start_composition_tick()`. Интервал —
  `config.COMPOSITION_TICK_SECONDS = 60` (0 — тик выключен);
- события берутся инструментом `list_events` календарного сервера
  (`yandex_calendar_server.py`) с `start=сегодня`, `end=сегодня+7`;
- текстовый вывод календаря разбирается в события оркестратором —
  `web/server.py::_parse_calendar_events`.

**Тест** — `tests/check_composition.py` §2 (разбор текста календаря в список
событий, включая события НА ВЕСЬ ДЕНЬ и пустой ответ). Тик-поток проверяется
запуском `serve()`.

---

### 2) «Время» — время от начала дня

**Требование (обновлённое):** MCP-сервер «Конвертер» переработан — теперь он
называется **«Время»** и отдаёт время от начала текущего дня (валютный
функционал удалён). Значение берётся из локального времени (`datetime.now()`).

**Реализация** — `currency_server.py` (id сервера — `currency` для
совместимости): `time_since_midnight` (HH:MM:SS), `minutes` (M:SS),
`hours` (HH.HHH, десятичные часы), `ping`.

**Тест** — живой MCP-прогон (`mcp_status`/`mcp_call_tool`, server_id=`currency`);
см. `tests/check_composition.py` (сервер входит в состав композиции).

---

### 3) «Замполит» — правило «время события → ФОРМАТ вывода времени»

**Требование (обновлённое):** «"замполит": событие с 0 до 12 — вывод В МИНУТАХ;
событие с 12 до 24 — вывод В ЧАСАХ; событие на весь день — вывод БЕЗ ИЗМЕНЕНИЯ
в HH:MM:SS».

**Реализация** — `zampolit_server.py`:

- `classify_time(time_str, all_day=False)` — по часу события выбирает ФОРМАТ:
  `all_day` или пустое время → `full` (период «весь день», HH:MM:SS);
  `< 12` → `minutes` (период «00:00–12:00»); `>= 12` → `hours`
  (период «12:00–24:00»);
- `format_time(time_str, mode)` — приводит время начала к формату
  (`minutes` → `M:SS`, `hours` → `HH.HHH`, `full` → `HH:MM:SS`); для события
  на весь день (нет времени) берётся начало суток → `00:00:00`;
- `classify_time_tool`, `format_for_event` — MCP-инструменты для одиночного
  события;
- `build_pairs(events_json)` — обработать СПИСОК событий (JSON от календаря),
  для каждого определить формат и вернуть JSON-массив пар
  `{event, start, mode, period, time}`.

События «Замполиту» передаёт оркестратор (`_composition_run`) — серверы
остаются раздельными stdio-процессами. Событие «на весь день» календарь отдаёт
БЕЗ времени (только датой, напр. `2026-09-30`), оркестратор помечает его
`all_day: true`.

**Тест** — `tests/check_composition.py` §1: 09:30→minutes (570:00);
12:00→hours (12.000); 00:00→minutes; 23:45→hours (23.750); «только время»
15:10→hours; весь день→full (00:00:00). §2 — распознавание события на весь
день из текста календаря.

### 4) «Завхоз» — сохранение результата в JSON

**Требование:** «"завхоз" mcp сервер который берёт данные от "замполита" и
сохраняет результат в json файл».

**Реализация** — `zavhoz_server.py`:

- `save_pairs(pairs_json, source)` — принимает ЛИБО объект `{"pairs": […]}`,
  ЛИБО «голый» массив пар, и атомарно пишет снимок в
  `session/zavhoz.json` (папка `session/` не коммитится);
- `load_pairs()` — чтение снимка (JSON-строкой);
- `info()`, `clear()` — сводка/очистка.

**Тест** — `tests/check_composition.py` §3 (сохранение 3 пар, чтение обратно,
приём массива пар).

---

### 5) «Доска» — таблица «событие ↔ время» по запросу

**Требование (обновлённое):** «"доска" mcp сервер который по запросу
пользователя в чате выводит данные "завхоз" в виде таблицы, где сопоставлены
события и время (в выбранном «Замполитом» формате)».

**Реализация** — `doska_server.py`: читает тот же `session/zavhoz.json`, что
записал «Завхоз», и печатает таблицу:

- `show_board()` — текстовая таблица (колонки: событие, начало, период,
  формат, время), ширины подстраиваются под содержимое;
- `show_board_html()` — HTML-таблица для ответа в чате (значения
  экранируются).

**Тест** — `tests/check_composition.py` §4 (заголовки/время/события),
§5 (пустое хранилище → сообщение-заглушка).

### Отдельная кнопка запуска композиции (раздел MCP)

**Требование:** «для данного режима сделать отдельную кнопку для запуска
композиции в разделе MCP».

**Реализация:**

- `index.html` — кнопка `#mcp-compose` («Запустить композицию») и поле отчёта
  `#mcp-compose-status` в блоке MCP;
- `js/app.js` — обработчик кнопки вызывает `mcpAction("compose")` и рисует
  отчёт (`renderComposeStatus`);
- `web/server.py::_handle_mcp` — действие `action == "compose"` запускает
  `_composition_run()` (пайплайн календарь → замполит → завхоз) и возвращает
  отчёт вместе с состоянием MCP.

**Тест** — живой прогон `_composition_run` (заглушка MCP): проверены шаги
`calendar → calendar_parsed → zampolit → zavhoz`, пары `minutes` (09:30 →
`570:00`) и `hours` (15:00 → `15.000`), сохранение 2 пар.

## Уточнения логики работы композиции

Ниже — три уточнения к исходной логике и их реализация.

### A) Композиция не связана с чекбоксом «Использовать MCP»

**Требование:** композиция запускается кнопкой независимо от того, включён или
выключен чекбокс «Использовать MCP».

**Реализация:** действие `compose` в `web/server.py::_handle_mcp` НЕ проверяет
`_ServerState.mcp_enabled` — кнопка всегда запускает `_composition_run()`, а тот
сам поднимает нужные MCP-серверы (каждый — отдельный stdio-процесс через
`mcp_client`). Кнопка `#mcp-compose` в `index.html` не блокируется чекбоксом.

**Тест** — `tests/check_composition.py` §6: `_composition_run` успешен при
любом состоянии чекбокса (зависимости от `mcp_enabled` нет).

### B) После запуска композиции — отдельное сообщение со списком MCP-серверов

**Требование:** после нажатия «Запустить композицию» вывести отдельным
сообщением названия всех задействованных MCP-серверов с кратким описанием их
работы.

**Реализация:**

- состав и описания — `config.COMPOSITION_SERVERS` (5 серверов);
- `_composition_run` кладёт состав в отчёт (`report["servers"]`);
- `_format_composition_message(report)` формирует текст-сообщение
  («Композиция MCP запущена…» + список «**Имя** — описание» + итог);
- `_handle_mcp` (action `compose`) возвращает `composition_message`;
- `js/app.js::pushCompositionMessage` добавляет это сообщение в поток чата как
  отдельный ответ («ассистент»).

**Тест** — `tests/check_composition.py` §6: в отчёте все 5 серверов; сообщение
содержит «Композиция MCP запущена», имена «Календарь/Замполит/Завхоз/Доска»,
описания и итог.

### C) Запрос к «Доске» сначала обновляет данные до актуального статуса

**Требование:** после запроса к «Доске» она обновляет информацию до
актуального состояния, а затем выводит данные.

**Реализация:** в `web/server.py::_handle_ask` вычисляется
`is_doska = (_ServerState.mcp_server == config.COMPOSITION_DOSKA_SERVER)` и
`via_mcp = (mcp_enabled or is_doska)`. Запрос к «Доске» идёт через MCP-путь
**независимо от чекбокса**; ПЕРЕД вызовом инструмента `show_board` оркестратор
прогоняет `_composition_run()` (календарь → замполит → завхоз) — данные
«Завхоза» обновляются, и только потом формируется таблица.

**Тест** — `tests/check_composition.py` §7: чекбокс ВЫКЛЮЧЕН, выбран сервер
«Доска» → запрос вывел таблицу доски (детерминированно, без выбора инструмента
моделью), обычный путь агента не вызван. Порядок при запросе к «Доске»: сначала
`calendar→list_events`, `zampolit→build_pairs`, `zavhoz→save_pairs`
(обновление), затем — инструмент вывода (`show_board_html`/`show_board`).

### D) Вывод «Доски» — детерминированный, без выбора инструмента моделью

**Требование:** при запросе к «Доске» таблица выводится надёжно (модель не
должна выбирать не тот инструмент).

**Реализация:**

- `js/app.js::ask()` — добавлен признак `doskaSelected` (сервер == «Доска»);
  при нём запрос НЕ блокируется проверкой «выберите модель или создайте
  персону» (константа `DOSKA_SERVER = "doska"`);
- сервер `_handle_ask` — при `is_doska` вызывается `_board_direct_result()`,
  который ДЕТЕРМИНИРОВАННО вызывает `show_board_html` и `show_board` (без
  привлечения LLM для выбора инструмента).

**Тест** — `tests/check_composition.py` §7: при `mcp_enabled=False`,
`mcp_server="doska"` запрос успешен, ответ содержит таблицу, обычный путь
агента не вызван.

## Как запускать проверки

Автономный (офлайн, без сети) тест логики композиции:

```bash
python tests/check_composition.py
```

Живой прогон MCP-серверов (нужны `mcp`):

```bash
python client.py zampolit_server.py   # инструменты «Замполита»
python client.py zavhoz_server.py     # инструменты «Завхоза»
python client.py doska_server.py      # инструменты «Доски»
```

Либо из интерфейса — кнопка **«Запустить композицию»** в блоке «MCP».
